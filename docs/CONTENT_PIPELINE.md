# Content pipeline

```text
Official Curriculum
        ↓
Reference Verification
        ↓
Lesson
        ↓
Worked Examples
        ↓
Questions
        ↓
Flashcards
        ↓
Formulas
        ↓
Interactive Tools
        ↓
Validation
        ↓
Testing
        ↓
Release
```

## Stage gates

1. **Official curriculum:** establish the correct topic, official module, outcome references, version, and official-versus-supplementary boundary.
2. **Reference verification:** record lawful local sources and verification status privately; never copy protected prose or commit extracted references.
3. **Lesson:** write original explanations against an approved scope map and stable route.
4. **Worked examples:** create complete problems, solutions, interpretations, and exam insights; independently recalculate every result.
5. **Questions:** create original three-option items with full option-level explanations and balanced answer placement.
6. **Flashcards:** distill atomic, self-contained recall and interpretation prompts without duplicating question stems.
7. **Formulas:** register each examinable relation with variables, meaning, example, mistake, classification, and lesson link.
8. **Interactive tools:** add only when interaction materially improves learning; validate inputs and test calculation services.
9. **Validation:** detect schema, count, classification, duplicate, orphan, broken-link, and private-artifact failures.
10. **Testing:** cover calculations, components, migrations, navigation, search, assessments, invalid inputs, and regressions as appropriate.
11. **Release:** run the complete checklist, update documentation and status records, report limitations, and use a scoped commit.

No stage may infer completion of a later gate. In particular, a lesson can be present while mathematical or source verification remains in progress.
